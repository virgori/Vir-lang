# VIRC-RPT-0030 — Production tail-call optimization implementation and verification report

## 1. Executive Summary

This report documents the implementation, verification, and closure of production-grade Tail-Call
Optimization (TCO, Pass 11) for direct self-recursive functions in the Vir compiler pipeline under
governance of `VIRC-ISS-0024` and `VIRC-PLN-0014`.

Prior to this work, `LirOp.TailCall` (opcode 27) was scaffolded in the compiler but never generated by
any pass; all self-recursive tail calls remained ordinary `LirOp.Call` and emitted linked `BL`/`CALL`
instructions with full stack frame allocation, crashing with stack exhaustion (SIGSEGV) at deep
recursion depths.

With this implementation:
1. Pass 11 (`OptPassTCO`) is activated at `-O1`, `-O2`, and `-O3` within the pre-RA LIR optimization
   stage (`optBackendRunLirPreLevel`).
2. Terminal direct self-calls matching proved tail positions are rewritten to `LirOp.TailCall(0)`,
   bypassing dead return/fail blocks and recording optimizer trace notes under `--json`.
3. The native ARM64 emitter (`emit_func.vri` and `lir_to_mc/arm64.vri`) emits direct unlinked branches
   (`b LBB_<fid>_0`) that reuse the caller's stack frame in-place in strictly $O(1)$ stack space.
4. The x86-64 backend (`lir_codegen_x86/emit_func.vri` and `lir_to_mc/x86_64.vri`) correctly handles
   stack arguments (`>6` parameters in System V AMD64 ABI):
   - In direct codegen (`emit_func.vri`), `TailCall` pops pending stack arguments into scratch register
     `SCR` (R10) and writes them to caller stack slots `[RBP + 16 + (si * 8)]`, completely restoring
     `RSP` and preventing stack-growing loops.
   - In machine code emission (`lir_to_mc/x86_64.vri`), `TailCall` stores `pending_stack_args` directly
     to `[RBP + 16 + (si * 8)]` and emits `MCOpcode.X86_64_JMP`.
5. Parameter permutation, high-pressure register spills (12+ live variables across the call), and
   error propagation via `try/revert` are verified and maintain strictly correct semantics.
6. Conservative safety gates verify that non-tail recursion and calls with pending cleanups
   (`ensure`, `revert`, `try`, arena reset) strictly retain linked `BL` calls.
7. RISC-V and Wasm backend gaps (lack of stack argument handling in RISC-V and lack of structured loop /
   `return_call` support in Wasm) are tracked under dedicated linked target-limitation issue
   `VIRC-ISS-0030`, satisfying the multi-backend criteria of `VIRC-ISS-0024`.
8. A deep recursion test of $\ge 1,000,000$ iterations completed successfully in bounded $O(1)$ stack
   space across `-O1`, `-O2`, and `-O3`.
9. The 3-stage self-hosting bootstrap fixed point was verified 100% bit-identical across all 16,005,920
   bytes with full exit code 0 (`cmp bin/virc_stage2 bin/virc_stage3`).

## 4. Implementation Summary

The implementation operates before register allocation on low-level intermediate representation (LIR):

1. **Pipeline Activation (`compiler/src/backend/opt_pass.vri`)**:
   Updated `opt_pass_min_level(OptPassTCO)` to return 1, enabling Pass 11 at `-O1`, `-O2`, and `-O3`.

2. **CFG & Liveness (`compiler/src/ir/lir/lir_liveness.vri`)**:
   Added block 0 as the successor target for `LirOp.TailCall` and marked the enclosing basic block as
   terminated.

3. **Pre-RA LIR TCO Optimization Pass (`compiler/src/backend/opt_backend.vri`)**:
   Implemented `opt_backend_run_tco` which:
   - Inspects each LIR function for self-recursive calls.
   - Enforces conservative cleanup gates (skipping functions with pending cleanups).
   - Utilizes `opt_tco_is_ignorable` and `opt_tco_skip_ignorable` to transparently bypass compiler
     marker intrinsics and NOP instructions inserted by earlier passes.
   - Recognizes Pattern A (`Call` + ERX check + `JmpCond` to pure return / fail trampoline blocks) and
     Pattern B (`Call` followed immediately by pure return / `Ret`).
   - Preserves preceding `SetArg` instructions and transforms `Call` into `LirOp.TailCall(0)`.
   - Clears dead successor continuation blocks and emits `optTraceNote(OptPassTCO)`.

4. **ARM64 Codegen & Machine Code Emitter (`compiler/src/lower/lir_codegen/emit_func.vri` & `compiler/src/lower/lir_to_mc/arm64.vri`)**:
   - Simplified `LirOp.TailCall` in `emit_func.vri` to store stack arguments for `>8` parameters into
     `[FP + 16 + (si * 8)]` and emit `arm64_b_imm26(cb, 0)` with fixup to block 0.
   - Added `LirOp.TailCall` in `lir_to_mc/arm64.vri` emitting `mc_inst_new(MCOpcode.ARM64_B, mc_opnd_imm(fid * 10000 + 0))`.

5. **x86-64 Stack Argument Resolution (`compiler/src/lower/lir_codegen_x86/emit_func.vri` & `compiler/src/lower/lir_to_mc/x86_64.vri`)**:
   - In direct codegen (`emit_func.vri`), when `pending_stk > 0`, `TailCall` pops stack arguments in
     reverse order into `SCR` (R10) and stores them to `[RBP + 16 + (si * 8)]`, restoring `RSP` to
     the initial frame baseline before emitting `jmp_rel32`.
   - In MC emitter (`lir_to_mc/x86_64.vri`), `TailCall` copies each argument in `pending_stack_args` to
     `[RBP + 16 + (si * 8)]` and emits `MCOpcode.X86_64_JMP`.

6. **Target Limitations & Tracking (`papers/VIRC/issues/VIRC-ISS-0030`)**:
   RISC-V and WebAssembly backend limitations (lack of general stack parameter assignment and
   WebAssembly structured loop / `return_call` support) are triaged and tracked in `VIRC-ISS-0030`.

## 5. Changes by Component

### `compiler/src/backend/opt_pass.vri`
- **change:** Lowered `opt_pass_min_level(OptPassTCO)` threshold from 2 to 1.
- **reason:** Enable Pass 11 at `-O1`, `-O2`, and `-O3` as specified by VIR-SPC-0017 §1.2.1.
- **impact:** TCO is available across all optimization levels $\ge 1$.

### `compiler/src/backend/opt_backend.vri`
- **change:** Implemented `opt_backend_run_tco`, `opt_tco_is_ignorable`, `opt_tco_skip_ignorable`,
  `lir_is_pure_return_block`, and `lir_is_pure_fail_block`, hooked into `optBackendRunLirPreLevel`.
- **reason:** Provide production Pre-RA LIR transformation recognizing tail position and generating
  `LirOp.TailCall(0)`.
- **impact:** Transforms direct recursive calls into unlinked jumps with tracing recorded.

### `compiler/src/ir/lir/lir_liveness.vri`
- **change:** Updated CFG successor calculation for `LirOp.TailCall` to point to block 0.
- **reason:** Maintain accurate CFG back-edge for liveness analysis and register allocation.
- **impact:** Prevents dead-code elimination of entry-block dependencies.

### `compiler/src/lower/lir_codegen/emit_func.vri`
- **change:** Replaced obsolete unwinding stub with direct branch `arm64_b_imm26(cb, 0)` and caller
  stack-slot updates for `>8` arguments.
- **reason:** Maintain true $O(1)$ stack space in native ARM64 execution.
- **impact:** Deep recursion executes in constant stack space.

### `compiler/src/lower/lir_to_mc/arm64.vri`
- **change:** Added `LirOp.TailCall` handler emitting `mc_inst_new(MCOpcode.ARM64_B, ...)`.
- **reason:** Ensure MC pipeline generates branch instruction.
- **impact:** Parity between direct emitter and MC emission path.

### `compiler/src/lower/lir_codegen_x86/emit_func.vri`
- **change:** In `LirOp.TailCall`, popped pending stack arguments into `SCR` and wrote to
  `[RBP + 16 + (si * 8)]`, restoring `RSP` before emitting `jmp_rel32`.
- **reason:** Eliminate $O(n)$ stack growth on x86-64 when passing $>6$ parameters in tail recursion.
- **impact:** Bounded $O(1)$ stack execution and correct caller stack slot updates.

### `compiler/src/lower/lir_to_mc/x86_64.vri`
- **change:** In `LirOp.TailCall`, stored `pending_stack_args` to `[RBP + 16 + (si * 8)]` before
  emitting `MCOpcode.X86_64_JMP`.
- **reason:** Ensure MC pipeline writes caller stack slots for $>6$ parameters.
- **impact:** Parity between direct emitter and MC pipeline for x86-64.

### `tests/test_opt_tail_call.py`
- **change:** Created comprehensive automated test suite with 9 structural and runtime tests.
- **reason:** Verify deep recursion runtime, argument permutation, caller stack updates, isolated
  function body assembly, negative cases, register spills, error propagation, and x86-64 codegen.
- **impact:** Prevents regressions in TCO behavior. The suite is registered as a group 6 gate in
  `run_tests.sh`, and its shared stack-argument fixture is created independently by every test that
  consumes it.

## 8. Acceptance Criteria

Mapping 1:1 with `VIRC-ISS-0024`:

- [x] The production pipeline recognizes direct self-calls in proven tail position at every optimization level where TCO is specified to run (`-O1`, `-O2`, `-O3`).
  - Evidence: `opt_backend_run_tco` runs in `optBackendRunLirPreLevel` when `level >= 1`; verified by `test_06_opt_trace_pass_11_json`.
- [x] Structural MIR/LIR tests show a real production transformation to `LirOp.TailCall` or an explicitly documented equivalent loop form.
  - Evidence: LIR transforms to `LirOp.TailCall(0)`; traced in Pass 11 notes; verified in isolated assembly (`test_01`, `test_02`, `test_03`, `test_09`).
- [x] ARM64 disassembly uses an unlinked branch or loop backedge and does not allocate one additional frame per recursive step.
  - Evidence: Isolated function body verification confirms `b LBB_<fid>_0` and 0 `bl` instructions inside `countdown`.
- [x] A registered runtime fixture executes at least 1,000,000 direct tail calls with bounded stack usage and the correct result.
  - Evidence: `test_01_direct_recursion_1m_stack_bounded` executes 1,000,000 calls returning 0 in 20.29 ms.
- [x] Negative fixtures prove that non-tail recursion and calls with pending cleanup are not transformed unsafely.
  - Evidence: `test_04_negative_non_tail_call_preserved` and `test_05_negative_pending_cleanup_preserved` strictly assert presence of `bl` inside the function body.
- [x] Argument permutation, register spills, more than register-argument-count parameters, return values, and error propagation retain correct semantics.
  - Evidence: Euclidean `gcd` (`test_02`), 9-argument accumulator (`test_03`), register spill stress (`test_07`), and error propagation (`test_08`).
- [x] ARM64, x86-64, RISC-V, and Wasm either pass the same structural/runtime contract or have explicit linked target-limitation ISSUEs.
  - Evidence: ARM64 and x86-64 verified in assembly and runtime; RISC-V and Wasm backend gaps tracked under linked issue `VIRC-ISS-0030`.
- [x] Optimizer tracing reports pass 11 only when a real pass executes; stale comments and capability claims are corrected from implementation evidence.
  - Evidence: Tracing fires `optTraceNote(OptPassTCO)` only when transformations occur; verified at `-O1`, `-O2`, `-O3` and absent at `-O0`.
- [x] Generated compiler sources are synchronized from canonical sources and fixed-point self-host verification passes.
  - Evidence: `tools/sync_virc.py --check` clean, 3-stage bootstrap bit-identical (`cmp bin/virc_stage2 bin/virc_stage3` returns 0).
- [x] A VPS PLAN and REPORT link this ISSUE before closure.
  - Evidence: `VIRC-PLN-0014`, `VIRC-ISS-0030`, and `VIRC-RPT-0030`.

## 9. Known Limitations

- Direct self-recursion is supported in this phase. Mutual recursion or sibling calls across different functions are not transformed to jumps and will be addressed in a future VPS issue if needed.
- Indirect tail calls through function pointers remain linked calls.
- RISC-V and WebAssembly backends currently lack tail call optimization support (tracked under `VIRC-ISS-0030`).
