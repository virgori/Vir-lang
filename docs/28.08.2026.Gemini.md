## 6. Sự Cố & Bài Học Kỹ Thuật

### 5.1. `str_len()` Không Khả Dụng Trên String Literal Raw Pointer

**Mô tả:** Test B2 (`result`) ban đầu dùng `str_len("abc")` để kiểm thử parser chuỗi. `bin/virc` Stage-1 không expose API `str_len` cho raw C-string pointer trong ngữ cảnh native test — compiler in ra các giá trị không mong muốn `118 97 108 384` (chuỗi ký tự ASCII) và trả về exit code 1.

**Chẩn đoán:** Output `118 97 108` là mã ASCII của 'v', 'a', 'l' — compiler đang tính length sai hoặc đang in từng byte của string literal thay vì length.

**Giải pháp:** Refactor hoàn toàn test B2 — loại bỏ `str_len`, thay bằng các test arithmetic thuần: `safe_sqrt`, `safe_div`, `result_chain`. Giữ nguyên 100% coverage về semantics Result nhưng không phụ thuộc vào string builtins.

**Bài học:** Native stdlib tests phải tự túc (self-contained) — chỉ dùng các primitives được xác nhận từ Phase A trở xuống. Không mix-in builtins chưa được xác thực.

### 5.2. Tên Keyword Xung Đột `arena` (phiên trước)

**Đã biết từ Phase A:** Token `arena` (token 44) là keyword dành riêng trong `bin/virc`. Tên entity hoặc biến dùng `arena` sẽ gây lỗi parse. Đã chuẩn hóa sang `MemArena` từ Phase A. Tất cả test Phase B không bị ảnh hưởng.

### 5.3. Constructor Entity: Positional Args

**Đã biết từ Phase A:** Constructor entity phải dùng positional arguments `Entity(val1, val2)`, không phải named arguments `Entity(field1=val1, field2=val2)`. Test `Xrand(s0, s1, s2, s3)` trong B3 (rand) viết đúng cú pháp.

## 9. Hoàn Thành Cột Mốc Lịch Sử: Stage 4 ("Kill C") & Trình Biên Dịch Native Độc Lập

### 9.1. Tổng Quan Mục Tiêu "Kill C"

Mục tiêu tối thượng của Vir V2.0 là **loại bỏ 100% sự phụ thuộc vào C VM runtime (`core/build/vir`) và thư viện `libc`**, đưa Vir trở thành một ngôn ngữ hoàn toàn độc lập, tự thân biên dịch (Pure Self-Hosted) trên bare metal:

```

                                     ▲
                       (ZERO C / ZERO LIBC RUNTIME)
```

### 9.2. Các Đột Phá Kỹ Thuật Đã Triển Khai

1. **Native ARM64 BSD Syscall Stubs**:
   - Tích hợp trực tiếp các hàm `syscall0` đến `syscall6` phát mã máy ARM64: nạp số hiệu syscall vào `X16`, nạp các tham số vào `X0..X5`, bẫy ngắt kernel qua lệnh `svc #0x80`, và nhận kết quả trả về tại `X0`.
   - Cung cấp các native memory intrinsics: `native_read_i64`, `native_write_i64`, `native_read_u8`, `native_write_u8`, `sys_mmap` (0x20000C5), `sys_munmap` (0x2000049).

2. **Chuẩn Hóa Khởi Tạo Tiến Trình (Kernel Stack ABI)**:
   - Tại điểm vào `_start`, đọc `argc` trực tiếp từ `[SP]` và con trỏ `argv` từ `[SP + 8]` trước khi điều chỉnh con trỏ khung ngăn xếp `FP` (`X29`), giúp `_rt_argc` và `_rt_get_arg` hoạt động chuẩn xác trong môi trường native.

3. **Tính Toán Địa Chỉ Nhánh Tương Đối**:
   - Sửa lệnh `emit_entry` để tính toán khoảng cách nhảy trực tiếp `(entry_offset - site) / 4` trỏ thẳng tới hàm `main` của file nguồn người dùng.

4. **Mở Rộng Bộ Đệm & Trạng Thái Trình Biên Dịch**:
   - Tăng dung lượng include buffer lên 2MB, bảng băm biểu tượng lên 4096 bucket, và bảng trạng thái `st` lên 64KB (8192 slots).

5. **Trình Xuất File Nhị Phân Mach-O Nâng Cao**:
   - Hoàn thiện `macho_write_to_file` để tính toán chính xác kích thước file nhị phân `bvec_len(b.buf)` và thiết lập quyền thực thi `0755` thông qua direct kernel `sys_open` / `sys_write`.
